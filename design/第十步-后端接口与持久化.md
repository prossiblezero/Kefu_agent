# 第十步：后端接口与持久化

**状态（2026-09-14）：首版实施设计，尚未实现。** 延续单 FastAPI、单 Worker、多任务并发；本步把第二至九步落实为数据、接口和事务边界。

## 1. 推荐实现与数据归属

采用 **SQLAlchemy 2 Core＋psycopg 异步驱动＋Alembic**：复用连接、事务与迁移，不自写 ORM 或迁移框架。每个并发操作使用独立连接／事务；网络请求和模型推理不持有数据库事务。插件只获得需要的仓储能力，第四步的读取、工作、执行、迁移角色分别建连接池，不让工具拿管理员连接。

| 表族 | 核心记录与约束 |
|---|---|
| `principals / sessions` | 消费者、访客、人工账号；服务端会话摘要、有效期、撤销状态。身份来自会话，不接受前端传入的 owner |
| `products / devices / purchases / dealers` | 标准产品、用户设备、购买记录及渠道依据；设备独立于型号。模拟记录带 `is_simulated`，不参与真实资格确认 |
| `tasks / task_work` | tasks 保存权威状态、归属、人工分配、预算和版本；task_work 保存 TODO、观察、候选与当前卡片／草案，按第三步类型校验 JSONB |
| `events / actions` | 事件追加保存来源、操作者与结果；actions 保存冻结草案、确认事件、唯一 operation_id、提交与核验状态。工具不能写用户确认或业务回执 |
| `jobs / model_calls / budget_buckets` | 持久待办及执行租约；模型请求、attempt、预算预留及用量；按日共享预算行。统一按“全局额度→任务额度”顺序加锁预留，避免并发超支与锁序倒置 |
| `artifacts` | 原始材料和临时上下文的类型、所有者、任务、存储键、哈希、来源及清理状态；原件与临时副本生命周期不同 |
| `documents / document_scopes / chunks / approved_steps` | 文档版本、产品／地区／时间范围、章节与向量、审核步骤；同一正文可有多条适用关系 |
| `memories / memory_exclusions` | 第六步的记忆、来源及可选经验向量；遗忘范围与来源禁用记录，防止旧作业重新提炼 |
| `tickets` | 首版模拟业务后端的工单、operation_id 唯一约束、接续结果；真实接口接入后以业务端回执为准 |

关系、身份、状态和常用过滤字段用列、外键与唯一约束；内容多变的观察和卡片用带 schema_version 的 JSONB。来源引用统一为 `kind/id/version/location`，没有来源的字段标记未知。任务内事件序号唯一且递增；设备／购买记录须同时核对用户归属，禁止仅靠型号关联。认证仓储只允许按凭证／令牌摘要执行固定查询，认证结果再进入业务 RLS；事件写入结合数据库角色和允许的事件类型约束，不能仅相信 payload 中的 producer 字段。

tasks 区分 **revision**（每次状态修改）、**input_version**（新用户输入、产品／授权等影响决策的变更）与 **lease_epoch**（执行者代次）。模型响应绑定输入及来源版本，不能因自身用量记录更新就误判过期；旧 Worker 所有写入需匹配 lease_epoch。

## 2. 身份与接口

首版不开放自助注册：维护者用 CLI 创建演示消费者和人工账号，密码复用 argon2-cffi 哈希。访客可创建隔离会话，只查公开知识及本人上传；不能查私人订单、提交需已认证账号归属的升级。登录不等于现实身份或购买资格核验。访客 Cookie 与登录 Cookie 分开，登录后优先使用账号会话；用户明确选择接续时验证仍有效的本人访客会话，原子转移资源、使旧执行版本失效并撤销访客会话，不自动合并任意任务。

会话令牌用标准库生成 32 字节随机值，数据库只存哈希；Cookie 使用 HttpOnly、Secure、SameSite=Lax，消费者／访客默认 7 天、人工 8 小时有效。首次建立无业务权限的访客会话只检查同站 Origin，取得会话后修改接口检查 Origin 与会话绑定的 CSRF token，登录和接续同样检查；登录轮换账号会话，注销立即撤销会话。人工账号只见已分配任务，分配由维护者 CLI 完成，不开放自行领取任意任务。

| API（统一 `/api` 前缀） | 语义 |
|---|---|
| `POST /session/guest`、`POST /session/login`、`POST /session/logout`、`GET /session` | 建立／撤销会话、返回身份与 CSRF token；登录限流，不区分账号不存在与密码错误 |
| `POST /session/adopt` | 已登录者显式接续其仍持有有效访客会话的任务；同时验证两个会话，禁止提交任意 guest_id |
| `POST /tasks`、`GET /tasks`、`GET /tasks/{id}` | 创建、分页查询本人任务、读取权威快照及事件游标 |
| `POST /tasks/{id}/messages` | 文本及已上传材料 ID；持久化后返回 202 和消息 ID，模型处理异步进行 |
| `POST /tasks/{id}/uploads`、`GET /materials/{id}` | 上传图片与授权查看原件；服务端分配 ID，不接受模型指定下载 URL |
| `POST /tasks/{id}/events` | 仅接受产品确认、步骤反馈、升级确认、停止／继续等固定事件；每种 payload 独立校验，不能提交通用“状态更新” |
| `GET /tasks/{id}/events?after=...` | SSE，按已持久化序号补发授权的界面事件；不是模型原始输出流 |
| `GET /me/memories`、`POST /me/memories/{id}/corrections`、`POST /me/memories/{id}/forget` | 展示、纠正与遗忘本人的记忆；保存新事件和排除范围，不暴露候选模型推理 |
| `GET /staff/tasks`、`POST /staff/tasks/{id}/updates` | 授权人工接续，提交进度、补充资料请求或带依据的处理结果；无法替消费者伪造操作反馈 |

事件请求携带 client_event_id、目标对象 ID 和预期版本。服务端先按“主体＋任务＋事件 ID”查幂等记录：同键同内容返回原结果，不同内容返回 409；再检查状态与权限。创建任务使用主体内唯一 create_key。状态冲突返回可刷新的快照位置；未授权资源统一返回 404，避免泄露存在性。其他错误用固定 `code/message/request_id/retryable`，不向前端发送 SQL 或 SDK 异常正文。

## 3. 事件、作业与恢复

```text
HTTP 事件 → 同一事务保存事件、状态变更、待办 → 提交 → Redis 通知
                          ↓                           ↓
                     PostgreSQL 待办 ← Worker 通知唤醒／定期补扫
                          ↓
                  认领 → 模型／工具 → 事务落结果 → SSE 补发
```

复用一个 jobs 表处理 run_turn、memory_extract、reconcile_action、cleanup_artifacts，不安装 Celery，也不把关键任务放 FastAPI BackgroundTasks。Redis Pub/Sub 只加快唤醒；Worker 每 5 秒查询到期作业补漏。jobs 以类型、目标 ID、输入版本组成幂等键。

Worker 用短事务 `FOR UPDATE SKIP LOCKED` 认领作业，并同时认领 task，确保同任务串行；调度器只读受限的作业 ID／类型／归属视图，再按数据库中的主体设置任务事务身份，工具不能访问全局调度视图。首版并发 4 个任务，本地 embedding 并发 1。租约 60 秒、每 15 秒续租，全部以数据库时间判断。丢失租约立即停止新动作；接管后 lease_epoch 增加，旧结果写入失败。租约不能撤销已经发出的业务请求，仍靠同一 operation_id 核验。

run_turn 结束时在一个事务内检查是否有未消费的新输入，再决定 WAITING 或安排后继轮次，避免唤醒丢在等待边界。前台优先，后台提炼在空闲槽执行。Memory 作业累计最多 2 次模型请求；达到上限标为待维护者处理，不能自动换 job_id 重开预算。动作未知先在 5／30／120 秒后核验，仍未知则保留暂停状态供人工处理，不能重新提交来试探。

**升级提交单独约束：** 确认事务冻结具体草案和接收方，按“任务＋草案 ID＋版本”唯一创建 actions；执行器校验后以 operation_id 调后端。模拟后端在独立事务创建唯一工单，可在提交成功后注入回执丢失，以验证真实崩溃窗口；故障注入仅在测试／本地演示开启。人工处理结果如仅为“建议已提供”，仍等待消费者反馈；明确核验恢复才可完成，用户可通过新输入重新打开未解决问题。

## 4. SSE 与隐私变更

快照带 last_event_seq，客户端从该位置接续；重复事件按序号去重。事件类型收敛为 message、progress、product_card、step_card、escalation_card、receipt、memory_changed、task_state，payload 带 schema_version 和相关对象版本。工具参数、后台摘要及用量明细不自动成为消费者可见事件。

SSE 每 15 秒心跳并复核会话／任务授权，失效即关闭；无通知时也从数据库补读，不能只依赖 Pub/Sub。历史事件对外采用当前权限下的投影，资料撤回或记忆遗忘后不重放被禁用正文。游标过旧时发 reset 事件，客户端重新读快照。只重连订阅不会创建新的 run_turn。

## 5. 验收、参考与取舍

必须验证：重复消息只处理一次；多标签页旧卡返回冲突；Worker 在提交前后崩溃能恢复；Redis 丢通知仍处理；旧租约无法覆盖新状态；RLS 跨用户拒绝；SSE 重连不漏已确认结果；遗忘期间的旧提取任务不写回。事务与 RLS 集成测试使用真实 PostgreSQL，不能用 SQLite 替代。

借鉴 [PostgreSQL 的队列认领语义](https://www.postgresql.org/docs/17/sql-select.html)、[Redis Pub/Sub 的投递限制](https://redis.io/docs/latest/develop/pubsub/)、[SQLAlchemy 异步事务](https://docs.sqlalchemy.org/en/20/orm/extensions/asyncio.html)与 [Alembic 迁移](https://alembic.sqlalchemy.org/en/latest/tutorial.html)。会话和密码复用 [OWASP 会话建议](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)及 [argon2-cffi](https://argon2-cffi.readthedocs.io/en/stable/howto.html)，不自写密码算法。来源核对于 2026-09-14。

ponytail：一个持久作业表和现有 Worker 足够，不加消息中间件或通用工作流服务。最脆弱的前提是外部工单端能按动作号核验；无法核验时必须如实保持未知，不能承诺端到端恰好一次。
