# 第十三步：实施路线与交付验收

**状态（2026-09-14）：第一至十三步形成首版设计基线；当前仅有设计文档，以下代码、命令与交付物均是实施约定，尚未创建或运行。** 后续按这份路线实现，不需要继续扩写架构才能开始开发。

## 1. 最终要交付什么

一套面向安克全产品的统一售后入口：文本／图片求助、产品消歧、适用知识检索、逐步操作与反馈、购买核验、受控升级和人工接续；底层包含持久循环、强制 TODO、资源授权、上下文外置、可更正记忆与预算管理。实际产品资料覆盖和模拟业务范围单独披露。

首版共享一个 Harness、11 个工具、3 份 Skill；生成模型默认托管 Qwen，embedding 默认本地 Qwen3-Embedding-0.6B，数据为 PostgreSQL＋pgvector，Redis 只承担唤醒／限流等非权威职责。模型候选和数值起点见第九、十、十二步，参数只能依据开发集与运行测量调整，不依据正式集反复调参。

## 2. 代码按职责放，避免重复框架

```text
Kefu_agent/
├── src/kefu/
│   ├── app.py / worker.py / cli.py   # HTTP、持久 Worker、维护命令
│   ├── contracts.py / settings.py   # 共享类型与配置、启动装配
│   ├── runtime/                    # 循环、执行检查、动作与预算
│   ├── plugins/                    # 模型、上下文、记忆、知识、售后工具
│   ├── storage/                    # 固定仓储、表定义、文件读写
│   └── api/                        # 会话、任务事件、SSE、人工接口
├── skills/                         # 三份通用 SKILL.md
├── web/                            # React 消费者页与人工接续页
├── migrations/                     # Alembic 迁移与数据库授权
├── data/sources.jsonl               # 可发布的来源清单
├── tests/ / evals/                  # 回归与效果评测，独立计量
├── deploy/                         # 镜像、代理、备份恢复说明
└── compose.yaml / pyproject.toml    # 环境入口与锁定依赖
```

这是职责分组，不要求每个概念建目录或基类；内容少时合并文件。SDK 类型在 plugins 内转换，runtime 不导入供应商 SDK，storage 不依赖 UI；Python 类型经 FastAPI OpenAPI 生成前端类型，开发时使用 [openapi-typescript](https://openapi-ts.dev/introduction)，不在运行时动态生成表单。

启动时显式装配已知插件：模型只生成结果，知识／Memory 返回带来源记录，上下文只构建投影；工具经统一执行器注册。循环、上下文、模型、记忆、存储的替换点采用小型 Protocol／普通对象，保留当前唯一实现及测试替身，不建插件依赖图、动态扫描、版本市场或热更新。插件生命周期只需启动初始化与关闭释放连接，安全检查不开放为可被插件覆盖的 hook。

## 3. 按可演示的增量开发

| 增量 | 实现内容 | 本增量即可验证的结果 |
|---|---|---|
| A：可用的知识服务入口 | 会话与隔离任务、RLS、持久 jobs、版本化资料导入、模型接入、TODO、消歧、精确／语义检索、最小长内容外置、来源展示 | 用户在网页提问并确认产品，获得适用证据；缺知识说明缺项。先开放只读服务，不展示尚未实现的提交按钮 |
| B：完整售后与恢复 | 操作卡及反馈、购买／质保工具、冻结升级草案、模拟工单、人工页、崩溃窗口与写入幂等检查 | 完成一次排障或有效移交；重启、重复确认及回执丢失不制造重复工单。只有此增量通过后才称完整业务闭环 |
| C：跨会话能力与效果证明 | Memory 提炼／更正／遗忘、完整压缩策略、多跳缺项衔接、48 条开发集与 240 条正式集 | 同设备隔天接续、不串设备；能解释多跳和记忆是否有收益，保留单跳成本对照 |
| D：可复现上线与交付 | 锁版本、资源测量、限流与总预算、HTTPS、备份恢复、浏览器验收、源码与演示包 | 干净环境可运行，在线演示可用，有真实评测报告与部署说明 |

数据建设随 A 开始：先盘点各品牌官方目录和资料范围，再抽取审核，不为凑 240 题生成虚假技术知识。每个增量保持已有功能可用；A 是受限只读服务，B 后才开放实际升级；安全验证与基本授权从第一增量就存在，不排到最后补。

单人实施可先按 4～6 周预留时间，其中资料核验和评测占独立工作量；这是排期估计，真实耗时取决于资料可获取性、模型表现和投入时间。功能回归与效果评测不计入产品代码预算，产品代码以数千行为目标而非硬限额，不为了行数删除正确性检查。

## 4. 维护与验证入口约定

CLI 用标准库 argparse，统一为 `python -m kefu.cli`，实现以下子命令：`create-user`（交互读取密码）、`assign-task`、`import-knowledge --manifest`、`seed-demo`、`inspect-task`、`set-budget`、`backup`、`restore`。不提供任意 SQL／任意 HTTP 子命令；seed-demo 与故障注入只对专用模拟环境开放，拒绝运行在真实业务配置上。

| 操作 | 实现后应提供的入口与验收 |
|---|---|
| 本地准备与启动 | `docker compose up -d postgres redis`；一次性 `docker compose run --rm migrate` 成功后 `docker compose up -d --build`，服务名与部署文件一致 |
| 后端回归 | `python -m pytest tests`，含独立 PostgreSQL／Redis 测试环境；模型协议测试用固定响应，不能计为真实模型效果 |
| 前端构建与交互 | web 目录执行 `npm ci`、`npm run build`、`npx playwright test`；验证主要卡片、断线与冲突路径 |
| 开发效果 | `python evals/run.py --split dev --trials 1`；固定模型、知识与场景版本，生成逐例记录 |
| 正式效果 | `python evals/run.py --split test --trials 3`；240 条基础场景独立复位，派生鲁棒性测试另列，开放式用户反馈按第八步完成 |
| 恢复演练 | CLI backup／restore 在隔离环境执行，校验材料、删除清单与未决动作后才开放；失败不得标注上线验收通过 |

仓库 CI 执行格式／类型、后端回归、前端构建和关键浏览器流程；不在普通 PR 上自动跑付费模型评测。真实评测在独立环境由维护者显式启动，单独设置可承担的评测额度，不占用公网演示日额度；任务与尝试用量仍完整记录，失败样本保留原因，不删除后重算成功率。

## 5. 最终交付门槛

| 设计责任 | 可检查的交付证据 |
|---|---|
| 循环与 TODO（2、3、9） | 规划强制生效、截断不执行、预算可解释、事件唤醒而非浏览器持有任务 |
| 权限与持久化（4、10） | 两个用户及人工账号隔离；数据库真实 RLS 测试；重复写入、旧租约、未知回执案例 |
| 上下文与 Memory（5、6） | 长内容按需读回、结束回收、隔天接续、更正／遗忘与后台竞态测试 |
| 数据与 RAG（7、8） | 来源／使用条件清单、覆盖说明、检索与生成分开诊断、多跳完整证据链评测 |
| 页面与人工闭环（11） | 消费者完整流程、人工接续、失效卡片和 SSE 重连的浏览器记录 |
| 部署与成本（12） | 空白环境运行指南、锁版本、费用／资源记录、真实恢复演练；模拟与真实模型清楚区分 |

最终提交源码 ZIP、配置示例、运行指南、第三方归属与数据使用说明、评测报告、实际操作视频及精炼展示材料。ZIP 不含密钥、真实消费者资料、未经许可的手册全文、模型权重或无关 Commerce／欧莱雅历史资料。展示材料围绕三个可验证点：受控执行与恢复、可更正且带来源的记忆、产品适用范围内的 RAG 与多跳；不宣称生产修复率或复现论文收益。

源码和文档可本地完成；提交、推送、公开部署与发布沿用当次明确授权。本轮任务仅完成设计，不自动创建云资源或开始应用实现。

## 6. 最后一次简化检查

首版不增加多 Agent 调度、GraphRAG、独立 reranker、Milvus、模型网关、通用用户模拟 Agent、标注平台、插件市场或新的 RL 训练。后续扩展须对应开发集错误或测得的容量瓶颈；测试替身用于验证边界，不等于再造业务系统。

实施验证复用 [pytest](https://docs.pytest.org/en/stable/how-to/usage.html)、[Playwright](https://playwright.dev/docs/test-cli) 与前述成熟数据库／SDK。当前已明确的默认配置不代表完成性能验收；模型可用性、资料覆盖和机器容量由实施阶段测量，结果写回第八、九、十二步，不另起一套相互冲突的方案。
